# 账户、协作与内容版本 API

## 身份与权限

- `/api/v1/auth/register`、`/login`：注册或登录，返回短期 Access JWT；密码使用 Argon2 保存。
- `/refresh`：使用 HttpOnly、SameSite=Strict Cookie 换取新的 Access JWT，刷新令牌单次轮换；旧刷新令牌不可重放。
- `/logout`：撤销当前 Cookie 对应会话；没有 Cookie 时可通过 Access Bearer 撤销会话。退出后该会话的 Access Token 也失效。
- `/me`：查询当前账户。前端 Access Token 仅存于内存，不写入 localStorage。
- 非 GET 账户操作拒绝未允许的 Origin。TLS 终止部署必须配置实际外部 Origin，不应允许任意站点。
- 项目拥有者自动为 Owner；可按已注册邮箱加入 Editor / Viewer，成员角色修改不允许静默转移拥有权。
- Viewer 只读；Editor 可创建任务、编辑内容、取消/重试；Owner 负责内容批准、项目归档、预算配置、成员管理和审计查询。
- 非项目成员访问返回 404；成员越权返回 403。非生产环境仍保留开发 Service Token；生产禁用此入口。

## 项目与剧集

- `PATCH /projects/{id}`：Owner 修改名称、视觉规范、输出配置、预算额度或归档/恢复。
- Owner 的项目设置页提供“视觉风格与画幅”表单：风格说明写入 `style_guide.description`，画幅使用 shadcn/ui Select（基于 Radix） 提供竖屏 1080×1920、横屏 1920×1080、方形 1080×1080 预设，也可自定义宽高及帧率。预设只改变宽高，不覆盖帧率。表单约束：风格说明最多 10000 字符；宽高为 1–8192 整数像素；帧率为 1–120、最多三位小数。这里是前端输入范围，不代表尚未接入的渲染器已支持这些规格；现有后端对象仍是开放字典。
- 保存只提交 `style_guide` / `output_profile`，保留未管理的扩展键；旧的非文本 `description` 保持只读并原样保留。空输出配置不会暗填默认值，须明确选择或填写。可查看服务端已保存的完整配置，或用“还原已保存配置”放弃本次表单输入；未提交草稿不提供跨页面恢复。
- 风格配置在之后启动的编剧工作流中进入输入快照，不改写已有内容版本；输出配置当前仅持久化，图片生成与视频渲染未接入。归档只读，存在活动工作流时保存返回 409；失败保留草稿，结束或取消任务后可显式重试。Editor / Viewer 不开放项目设置修改权限；配置编辑仍不提供 CAS 冲突检测。
- `PATCH /episodes/{id}`：Editor 可修改标题、目标时长；归档/恢复仅 Owner。
- 前端工作区标题下的“编辑剧集”对 Owner / Editor 开放；Owner 也可在项目设置的剧集管理中编辑指定剧集。表单使用 shadcn/ui Dialog（基于 Radix），标题去除首尾空白后为 1–160 字符，目标时长为 2.5–1800 秒（最多三位小数，按整数毫秒提交）。保存后同步目录和工作区，并重新读取画布；刷新页面后仍保留修改。Viewer 不显示入口，已归档项目／剧集禁用编辑。
- 保存失败时弹窗保留草稿并显示服务端错误；活动任务须结束或取消后重试。取消或 Esc 放弃本次修改，不发送请求；保存中阻止关闭与重复提交。此操作不会重写已有内容版本，也不提供跨成员配置编辑的 CAS 冲突检测。
- 存在排队、运行或待审核工作流时，禁止改写相关生产输入；归档后只读，恢复必须单独操作。
- `/projects/{id}/members`：查看/添加成员；`/{user_id}` 修改角色或移除。
- `/projects/{id}/audit-events`：Owner 分页查询内容审核、成员及配置变更审计。
- `/episodes/{id}/runs`：分页查询工作流历史。

## 工作台历史分页（TXT-04）

- 项目、剧集、剧本版本、分镜版本、任务和执行事件使用服务端 `limit/offset` 分批读取。首批最多 100 条；共享 shadcn/ui Select（基于 Radix） 可将**后续每次追加**改为 20、50 或 100 条，不清空已加载内容。设置页的剧集管理与侧栏共享同一份分页状态。
- 统计明确显示“已加载 N 条”，只有服务端返回不足本次 limit 时才显示“已全部加载”。恰好整页时，需要再查询一次（可能为空）确认结束；不推测总数。追加失败保留已有内容和 offset，可显式重试；同一列表的追加请求串行，按 ID 去重，但 offset 按服务端原始条数推进。
- 列表刷新以 100 条为一批重新读取至少已展开的范围，可能补齐末批更多数据，但不退回首批；工作台内容刷新与活动任务轮询同样保留已展开范围。刷新与追加串行执行，写入后的刷新不会复用写入前的响应。切换项目、剧集或执行记录时取消旧列表请求，迟到结果不进入新列表。
- 当前项目可独立于首批列表恢复（包括页面重载）；新建或已选中的项目／剧集不会因不在首批而消失。这些独立保留的选中项不计入分页“已加载”数量。新增剧集的建议集数仅基于已加载目录，未加载全部时会提示核对，服务端仍拒绝重复集数。
- 版本列表只展示已读取的剧本、分镜及其镜头。完整依赖画布保持原有接口；点击尚未加载的旧版本节点，会继续分页读取到该精确版本，支持查看与原有编辑／审核操作，不再要求用户自行调用 API。
- 执行事件按时间从早到晚追加；切换任务会重置事件列表，空列表、加载中、失败和末页均有明确状态。分页读取对 Viewer 同样开放，不改变现有写权限。
- 边界：后端仍是 offset 分页，跨页请求不构成一致性快照；并发插入或重排可能移动边界，需使用“刷新”重新对齐已读范围。本项不增加总数接口、游标协议、虚拟列表或画布服务端分页，新版本自动定位见下文 TXT-05，分页协议本身不承担定位。
- 验收：浏览器通过真实 API 创建超过 100 个项目、剧集、剧本和分镜，验证旧数据访问与原有审核；大量任务／事件及网络竞态使用明确的浏览器网络夹具，另以 `backend/tests/test_pagination.py` 验证真实数据库的 105 个任务、200 条事件、相同时间戳稳定排序、末页和任务隔离。所有数据均位于测试临时库，无业务库及收费 Provider 调用。

## 不可变内容版本

- `POST /episodes/{id}/scripts`：`expected_version_no` 加完整结构化 `content`，保存人工新版本。
- `POST /episodes/{id}/storyboards`：另需 `script_version_id`，必须引用本剧集已批准的精确剧本版本。
- 内容版本只增不覆盖；版本号冲突返回 409。分镜还需通过场景/角色/台词引用及目标时长校验。
- `POST /episodes/{id}/{scripts|storyboards}/{version_id}/review`：Owner 审核人工版本，正文 `decision=APPROVE|REJECT`、可选 `comment`。
- 工作流生成版本不能从此接口绕过审核，必须使用原 `/runs/{id}/resume`，绑定具体版本和 revision。
- 前端在剧集起点选择“自己写剧本”，从空白表单创建人工剧本；保存前仅是本地草稿，保存后自动打开精确的新版本并显示待审核状态，由 Owner 显式审核。
- 前端在剧集起点选择“自己写分镜”，通过 shadcn/ui Select 选择本剧集已批准的精确剧本版本（包含超过 100 条的历史），再填写场景、画面、角色、时长、景别、运镜和字幕，可增删镜头。保存使用现有人工接口，不调用模型；结果为独立待审核版本，保存后自动定位精确新版本，由 Owner 显式审核。只读、归档或活动任务时禁止起稿；请求失败保留当前草稿，版本冲突需刷新后显式重试。
- 人工版本审核通过不会自动调用模型；在已批准剧本上选择“从此版本生成分镜”，显式启动独立导演任务。

## 人工新版本保存与定位（TXT-05）

- 人工剧本／分镜从零起稿或另存成功后，以 POST 回执中的类型和版本 ID 精确选中，不以当前最大版本号猜测，避免误选其他成员并发创建的新稿。
- 保留原来的画布／列表视图，自动打开内容与属性、移动焦点到新版本；画布等待真实节点载入后仅定位一次，不伪造节点依赖，也不覆盖已保存的布局坐标。
- 保存提示明确显示版本号和待审核状态；Owner 可以显式审核，Editor 等待拥有者审核。审核后提示同步状态，不自动批准，也不自动启动模型任务。
- POST 成功但 GET 刷新失败仍以回执展示已保存的版本，提示“无需再次保存”；重试只刷新读取，不重复 POST。回执仅作详情／列表展示兜底，不插入分页内部 rows，避免污染服务端 offset。
- POST 失败保留草稿；保存中防重复提交。收起提示不丢失已保存版本；切换剧集后丢弃旧剧集的迟到保存回执。
- 草稿离开保护见下节 TXT-06；后端版本冲突、审核权限及归档约束保持不变。

## 未保存草稿保护（TXT-06）

- 人工剧本、人工分镜（包括基于旧版本的修改）及故事灵感，输入时同步暂存到当前标签页的 `sessionStorage`。不新增 API，不自动生成版本，也不自动提交审核或模型任务。
- 存储按账号隔离，草稿键绑定剧集、内容类型、原始精确版本及起稿来源剧本 ID。修改不同历史版本互不覆盖，分镜切换来源也不混用；跨项目、剧集、视图、任务及设置页切换后仍可恢复。
- 内容与属性会提示本剧集有哪些未保存草稿。刷新后重新打开相同历史版本或“自己写剧本”入口即可恢复；人工分镜重新选择提示中对应的已批准来源版本后恢复。故事灵感自动恢复。
- 有草稿时注册浏览器原生 `beforeunload` 提醒；具体提示文字及是否弹出由浏览器决定，不依赖该事件保存内容。内容每次变动已同步写入，而非等离开时才写入。
- “放弃本次编辑”或“放弃草稿”使用现有 shadcn/ui（Radix）Dialog 二次确认；Escape／继续编辑保留输入，确认仅移除该份草稿，不影响服务器历史版本和其他草稿。未改动或完全恢复原始内容不计为草稿。
- POST 失败（包括版本冲突）保留草稿；POST 成功即清除本次提交对应草稿，后续 GET 失败不恢复保存入口。迟到的保存回执只清除与提交快照一致的记录，不覆盖切换后继续输入的草稿。提交期间冻结编辑字段；草稿恢复不绕过只读、归档、活动任务及后端权限限制。
- 存储读取、JSON 或恢复内容结构异常不会使编辑器崩溃；界面明确告警。配额不足／浏览器拒绝存储时退回当前登录会话内存，可切换恢复，但刷新、关闭或退出登录前必须先保存，否则内存内容会丢失。
- 这是标签页级临时恢复，不是云草稿、长期备份、跨设备同步或多标签合并。草稿以明文保存在同源会话存储，不含令牌；退出登录后不会展示给其他账号，同一账号在该标签页重新登录可恢复正常暂存记录。共享设备应保存后显式放弃草稿或关闭标签页，不应依赖浏览器会话恢复行为保护敏感内容。

## 从指定剧本启动导演

`POST /api/v1/episodes/{id}/storyboard-runs`，必需 `Idempotency-Key` 请求头，正文：

```json
{"script_version_id": "指定已批准剧本的 UUID"}
```

- 返回 202，格式与 `script-runs` 相同：`run_id`、`status`、`status_url`、`events_url`。
- Editor / Owner 可发起；Viewer 403，非成员或其他剧集的剧本 404；未批准剧本、归档项目／剧集或同剧集已有活动任务 409。
- 输入固定精确剧本 ID、正文快照和目标时长；不会调用编剧或新增剧本，不会在执行／重试时改用最新版。
- `workflow_type=storyboard`、`workflow_version=director-1.0`；旧 `1.0` 双审核图保留，已有 checkpoint 继续按原拓扑恢复。没有数据库结构变化，无需新增 Alembic revision。
- 两种启动入口共享同一剧集的幂等键空间；同键同正文返回原任务，同键不同正文／入口返回 409。成功提交后再次主动生成请使用新键。
- 只有分镜人工审核节点，仍用 `/runs/{id}/resume` 绑定精确版本和 revision；取消、失败重试、事件及重复消息保护复用既有协议。

## 画布

- `GET /episodes/{id}/canvas`：从实际剧本、分镜、镜头版本派生节点和依赖连线，不接受客户端伪造依赖。
- `PUT /episodes/{id}/canvas/layout`：保存 `positions`、`viewport`、`expected_revision`；版本竞争返回 409，不覆盖他人布局。
- 仅接受本剧集节点和有限坐标/缩放；只读成员不可保存布局。

## 数据库与部署边界

业务表通过 Alembic `0002` 增加账户、可撤销会话、项目成员、审计及画布布局，并兼容 `0001` 旧数据回填。
有人工内容版本时不能无损降级到要求 run_id 非空的 `0001`，迁移会在修改结构前拒绝；请先备份并制定数据迁移方案。

请求体默认限制 2,000,000 字节；账户 POST 默认每来源地址、每 API 进程 30 次/分钟。
多副本须在统一网关执行全局限流，反向代理部署还必须限定可信代理，不能盲目信任客户端转发头。
预算目前只保存额度，尚不执行费用预留/扣费；审计并非所有只读访问和所有运行事件的通用合规审计。
本功能不包含图片、对象存储、连续性审查和成片，不能将账户及版本接口的完成当作完整生产系统验收。

## 已保存版本差异（TXT-07）

在画布或版本列表中选中剧本／分镜后，点击右侧“查看版本差异”。界面复用 shadcn/ui（Radix）Dialog、Select、Card、Badge 等组件；没有引入第二套组件库。

```text
GET /api/v1/episodes/{episode_id}/scripts/{version_id}/comparison
GET /api/v1/episodes/{episode_id}/storyboards/{version_id}/comparison
    ?base_version_id={同剧集同类型的精确版本 UUID}
```

- 返回 `base`（可为 null）与 `target` 快照，包含正文、版本 ID／编号／当前审核状态、创建时间、可追溯作者、人工编辑来源、分镜引用剧本、生成任务与现有直接下游。
- 不指定基准时选择早于当前版本的最近同类版本；没有更早版本时按空内容比较。也可明确选择任意同剧集同类版本或自身。**比较基准不等于编辑来源**：从 v1 另存为 v3，默认基准可能是 v2，但来源仍为 v1。
- 人工保存接口新增可选 `base_version_id`，校验与新版本同剧集同类型，记入既有 `*.version_created` 审计；旧客户端可以省略。工作流首次成功启动时记录 `workflow.started`，幂等重放不重复记录。不增加表或数据库迁移。
- 人工作者来自版本创建审计；系统生成内容显示“系统工作流”及可追溯发起人，不能将发起人当成人工作者。不返回邮箱。历史作者或来源缺失时明确显示未记录，不推断为当前用户或上一版。
- 创建时间以带时区的 ISO 时间输出，界面按浏览器本地时区显示；不是最后编辑时间或审核时间。已有审核状态仍可能随人工审核改变。
- 按字段展示新增／删除／修改与前后原文，默认只看变化，可切换全部字段；区分不存在字段和空文本。场景／镜头按当前业务编号配对，对白按位置比较；尚无永久稳定条目 ID，因此插入、删除或重编号可能体现为多处字段变化。不是逐字符差异编辑器，也不包含未保存草稿。
- 历史基准选择沿用每次最多 100 条的分页读取，支持追加、刷新与失败重试；比较读取可独立重试。切换基准、切换内容或关闭弹窗会取消旧比较请求，避免迟到响应覆盖当前选择。
- 剧本影响统计精确引用它的所有分镜版本、这些分镜的镜头总数，以及 `workflow_type=storyboard` 且输入精确引用该剧本的独立导演任务数（不按任务状态过滤）。分镜影响只统计其镜头；分镜列表仅预览最新 20 条，计数不截断。双审核工作流不冒充独立导演任务统计。
- 读取先验证项目／剧集权限；跨剧集、跨类型、非成员无法读取目标或基准。Viewer 以及已归档项目／剧集仍可只读对比；对比不写审计、不修改历史、不触发自动失效或重建。
- 这不是完整资产依赖 DAG 或媒体影响分析；图片、音频、连续性审查与成片下游尚未实现。
