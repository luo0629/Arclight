# Arclight

**面向 AI 漫剧与视觉叙事的多智能体创作项目。**

让故事创作成为可审核、可追踪、可恢复的生产流程，而不是一组彼此独立的模型调用。

Arclight 面向个人创作者、小型漫剧工作室和 AI 内容制作团队，目标是连接故事、剧本、分镜、视觉素材与最终成片。创作者负责方向与关键决策，专业 Agent 承担具体创作任务，服务端负责状态、版本、审核和执行。

> **当前阶段：可用的故事文本创作产品。**
> 已实现可爱风画布前端、账户与项目协作，以及故事 → 剧本 → 分镜的双人工审核流程。图片、配音和成片生产仍在开发中。

## 为什么做 Arclight

AI 内容创作的难点不只在于生成一段文字或一张图片，还在于如何把不同环节组织成可持续修改、协作和交付的过程：

- **创作结果需要成为正式产物。** 剧本、分镜和镜头信息不能只存在于聊天记录中，需要保存、查询并关联具体版本。
- **关键决定需要由人确认。** 剧本和分镜是否通过，应当是明确的审核动作，而不是模型自行跳过的步骤。
- **中断不应丢失全部进度。** 工作流需要记录执行位置，支持等待审核、重启恢复和失败后的显式重试。
- **扩展模型不应改写业务流程。** 生成能力与业务逻辑分离，避免工作流绑定某个供应商的 SDK。

Arclight 先把文本创作与审核链路做实，再逐步向完整的漫剧生产流程扩展。

## 当前可以做什么

### 在贴纸画布上整理故事

React + TypeScript 前端统一使用 **shadcn/ui（Radix）组件与 Tailwind CSS v4**，采用纸白、奶油与荧光青柠的故事拼贴风格，配合原创手绘线描插画。产品首页提供登录与注册弹窗；项目切换、账号菜单、成员角色与加载反馈使用统一的现代交互组件。左侧管理项目与剧集，中间画布展示剧集、剧本、分镜和镜头，右侧阅读或编辑具体内容。

节点可以拖动，布局与视角保存到服务端；依赖连线来自真实版本关系，不能手工连线伪造审核结果。也可切换版本列表，不依赖画布操作；小屏幕保留列表与编辑入口。

注册登录后即可创建项目、添加剧集、输入故事。任务中心展示状态与事件，提供人工审核、取消和失败重试。项目拥有者可添加已注册伙伴，分别授予编辑或只读权限；设置页支持项目配置与归档恢复。

### 查看项目生产总览

项目导航中的“项目总览”汇总全项目已保存的文本生产记录，包括剧集阶段、待审核与确认数量、任务状态及最近任务。剧集目录独立分页，可直接进入对应画布或任务与审核页面；页面支持手动刷新，并在可见时每 15 秒刷新。

阶段根据最新文本版本和精确来源关系计算，工作流审核与产物不重复计数。预算上限与实际费用分别展示；成本账本、视觉资产审核和成片交付尚未接入，会明确显示能力缺失，不以零费用或分镜完成代替实际结果。

### 管理项目视觉资产目录

项目导航中的“视觉资产”支持创建、查看、改名、归档和恢复角色、场景、道具及风格目录。目录使用稳定 ID 和独立修订号，过期修改会提示冲突；Viewer 与归档项目只读。归档保留已有媒体版本和历史引用，恢复保留归档前状态。

资产资料支持简介、标签及年龄段、外观、发型、服装、体态、表情、色彩、材质。创建时可登记人工来源，创建者由服务器记录；历史缺失来源如实显示未知。使用范围可声明项目共用或选择本项目剧集，与实际引用查询分开。资料修改与改名共用修订冲突保护。

角色设定支持固定／允许变化特征、默认／可选服装、表情、初始与多角度参考图记录。参考图从本角色或本项目图片的已有精确版本选择，标准图由人工明确指定已批准版本；后续新增图片版本不会改变已有绑定。角色设定与资料、改名共用修订冲突保护。

场景设定支持空间布局、时间段、灯光、配色和环境，人工绑定该场景已批准的精确参考版本；同一版本可供多个镜头复用。关键道具支持外观、剧情状态与本项目已批准角色精确版本的持有者绑定。设定变化保留既有文本和镜头快照。

支持人工导入PNG/JPEG原图为不可变候选版本，保留原始字节、SHA-256、来源／使用权说明、创建者和创建时资产资料快照。历史版本可分页查询及鉴权预览；Owner可批准、拒绝或标记失效，归档／恢复保留原图与历史引用。批准后由Owner或Editor人工选用精确版本；新候选或新批准不会自动替换选用。历史原图可另存为可追溯的新候选，保留精确来源并重新审核。

选用、锁定和解锁同时校验目录修订与选用锁修订，冲突时刷新后重试。Owner可锁定当前精确版本，锁定时禁止修改资料、版本和选用；显式解锁恢复原状态。锁定与解锁均保留精确选用、原图及审计。

导入时可登记外部生成的服务、模型、提示词及版本、负面提示词、seed、参数和精确参考图片；服务端记录原图尺寸及参考版本名称／编号／哈希快照，历史另存保留来源。外部生成资料标为人工声明，人工图片与旧版本缺失信息分别显示，不补造模型调用记录。

每项资产可查询实际被哪些剧集、剧本场景和分镜镜头引用，显示精确图片版本、内容版本及审核状态，并直接打开对应内容。查询包含历史引用，与资料中的声明范围分别呈现；后续新图、改名或归档不会改变历史绑定。

Visual Bible 按画风、线条、渲染、配色、光照、构图、禁止元素和负面提示词逐字段维护；编辑及Owner锁定操作均另存不可变规范版本。锁定字段先显式解锁才可修改，Editor只能维护未锁字段；旧任意风格配置保留只读，设置页风格说明共用版本与锁定校验。后续文字任务冻结精确规范版本，历史任务输入保持原样。

SQLite 与 PostgreSQL 通过数据库触发器保护历史剧本、分镜、镜头、图片版本、故事来源及修订、提炼、大纲、Visual Bible、精确依赖、角色确认、审核和任务输入快照。直接 SQL 不能覆写或删除已保存内容、身份与来源，SQLite 替换写入及 PostgreSQL TRUNCATE 也受保护；正常审核、归档、失效、选用、解锁及追加新版本仍可执行。有历史数据时迁移拒绝移除保护；数据库管理员的 DDL 权限和数据库外文件修改不属于该保护范围。

精确依赖服务支持保存不可变输入清单，并在创建派生图片版本的同一事务中关联清单、产物回执和来源版本依赖边。可按精确来源／目标版本查询，也可有界批量查询上游或下游，读取和写入均受项目权限控制。清单保留服务器解析的版本号、哈希和资产身份快照；提示词、模型及参数上下文属于请求声明，不代表实际调用记录。旧依赖不补造清单，旧产物不能事后改绑来源；改名及新版本不改写历史清单。写入会校验项目归属、版本有效性、精确输入身份及类型组合，并在项目级写锁内拒绝自环和间接循环；同一资产的不同版本仍可合法派生。

依赖服务支持确定性失效传播：对白按稳定台词范围影响音频／字幕及下游，镜头顺序影响时间轴／成片；正式选用和文本批准触发变更，候选不会静默替换当前版本。清单冻结变更事件序号，晚到产物识别捕获后的输入变化并标记 stale，保留原始清单和来源；显式新任务仍可选择有效的历史批准稿。音频、预览、时间轴与成片的依赖合同不代表对应生成服务已实现。

文本批准、图片选用及版本失效／归档前会分析真实版本依赖。有受影响的下游时，确认界面列出精确版本、依赖原因及重新审核／生成／渲染动作；取消不修改数据。分析失败可重试，确认时在项目图锁内核对影响摘要，依赖变化会要求重新预览。只读成员也可查询影响清单，分析不会改写历史或自动调用生成服务。

失效分镜可从指定批准剧本单独重生成，并重新审核新版本。派生图片可逐项确认新输入，复用未改变的精确来源，再导入替换图或将原图另存为候选重新确认；候选通过审核后仍需人工选用。旧版本、旧依赖与未受影响产物保留。此入口使用现有导演任务和人工图片流程，音频、视频与自动图像生成仍待对应服务实现。

人工图片支持私有 MinIO／S3 与本机目录（`ARCLIGHT_ASSET_STORAGE_PATH`），Compose 默认使用 S3，既有本机历史仍可读取。新导入及历史另存均在版本事务中保存不可变文件回执，可按项目分页查询哈希、实际类型、大小、来源、使用权和精确版本，接口不返回私有对象键。原图最大1 MiB、400万像素、最长边4096，仅接受完整静态PNG/JPEG；对象键由服务端生成。S3 通过项目权限签发最长300秒的临时上传POST策略与文件下载地址，绑定服务端对象键、大小及类型。临时上传先经过完成接口读取、哈希和完整图片解码，复制至不可覆盖的新对象后才登记候选回执；已验证图片可创建精确资产版本，保留候选来源关联和既有审核门禁。上传统一校验用途／扩展名／真实格式／大小／哈希与完整解码：静态PNG/JPEG最多1 MiB／400万像素／4096边长，UTF-8 TXT/Markdown最多256 KiB，WAV/MP3/Ogg音频最多32 MiB／600秒／48 kHz／双声道，独立静态TTF/OTF最多8 MiB／2万字形。解析在不含服务凭证的独立进程执行，CPU 12秒、内存512 MiB、墙钟20秒，Linux使用资源限制，Windows使用Job Object；超限、截断、伪造格式、额外尾部、字体表校验错误或解析失败均拒绝完成。音频仅接受固定容器和编解码器，禁止外部资源；不接受视频、压缩文档、字体合集或可变／SVG字体。非图片候选尚不接入资产版本与媒体生产。对象安全回收及自动生产仍待后续任务。

### 从故事生成剧本与分镜

以项目和剧集组织创作内容。输入故事后，由编剧 Agent 生成结构化剧本；剧本通过人工审核后，再由导演 Agent 生成结构化分镜和镜头信息。

生成结果通过 Pydantic 合同校验并保存到数据库，分镜关联具体剧本版本，便于后续查询和核对。

“故事来源”支持保存文本或导入 TXT／Markdown，并保留原始字节、编码、来源、授权说明和内容哈希。文本和文件可以另存修订，历史版本始终保留；过期版本的修订会提示冲突，保存失败可恢复草稿并重试。提炼、大纲和编剧任务记录精确来源版本，也可从历史来源直接启动编剧，修订不会改变旧任务输入或已批准内容。随任务保存的手动输入会明确显示“未单独声明”授权，补录须另存修订。原稿保存在配置的私有本机对象目录或MinIO／S3，数据库仅保存来源元数据和对象引用；下载仍需要项目权限。列表不读取原文，详情与直接引用原稿的新任务按原字节哈希有界读取；已有任务沿用创建时快照，不依赖原稿的后续可用性。

也可以选择“自己写剧本”，从空白表单保存人工版本并审核；“自己写分镜”允许选择精确的已批准剧本手工起稿。人工保存成功后自动打开回执对应的新版本并显示待审核状态，不会误选并发新稿；读取刷新失败可单独重试，无需重复保存。对任意已批准的剧本，点击“从此版本生成分镜”即可单独启动导演任务：只使用选定版本，不重新调用编剧；分镜生成后仍需人工审核。

选择已保存剧本可发起“局部改写”：按单场景、章节（连续场景）或动作／台词中的选定段落，填写语气、对白字数或旁白比例等要求。服务端固定精确来源，只合并选区内的文字并另存待审核新稿，原稿和已有分镜保持各自的版本关系。改写由独立后台任务执行，Owner 审核通过后可显式启动导演；支持草稿恢复、幂等提交和失败重试。

### 在关键节点保留创作控制权

故事设定支持角色别名。剧本版本、提炼结果和任务审核页中的“角色匹配与确认”会匹配本项目角色的名称与别名；遇到多个匹配时由人选择，陌生角色须明确确认后才新增故事设定。归档角色需先恢复；模型不会自动创建视觉资产。每次角色确认保留精确来源和角色修订快照，与剧本审核分别处理。

剧本与分镜各有独立的人工审核节点。审核绑定具体内容版本和运行 revision，避免将过期审核结果应用到另一份内容。

审核通过后继续执行，驳回则终止当前运行。支持保存人工新版本并由项目拥有者审核；工作流生成版本仍必须通过对应任务审核，不可绕过版本绑定。

### 查看与恢复工作流

每次创作任务都有独立的运行记录、状态和业务事件。LangGraph checkpoint 保存编排进度，同一任务使用稳定的 thread ID，在人工审核后恢复原有流程。

后台任务支持幂等请求、重复消息去重、排队／待审核运行取消，以及失败后的显式重试。外部模型调用不承诺 exactly-once，重试可能产生额外调用费用。

媒体 Worker 使用数据库执行租约和独立心跳，提交与只读查询期间不持有业务行锁。进程重启后，beat 会扫描过期执行与待查询的异步任务，沿原 attempt 对账；缺少明确证据时进入人工处理，不盲目重发。过期执行者的迟到回执不能覆盖当前状态，原回执与审计保留。`ARCLIGHT_MEDIA_LEASE_SECONDS`、`ARCLIGHT_MEDIA_HEARTBEAT_SECONDS` 和 `ARCLIGHT_MEDIA_POLL_SECONDS` 配置租约、心跳与查询间隔，心跳必须短于租约的一半。

### 在无模型密钥的环境中演示

默认 Mock Provider 可以演示完整的文本审核流程。仓库也提供 OpenAI-compatible 文本适配器，使用结构化输出协议接入模型服务；真实供应商仍需配置和联调。

## 创作流程

```text
创建项目与剧集
      ↓
   输入故事
      ↓
编剧 Agent → 保存剧本版本
      ↓
  人工审核剧本 ── 驳回 → 结束
      ↓ 通过
导演 Agent → 保存分镜与镜头
      ↓
  人工审核分镜 ── 驳回 → 结束
      ↓ 通过
  本次创作任务完成
```

这里的“完成”指剧本／分镜任务完成，不代表图片、配音或视频已经生成。

## 设计思路

| 原则 | 在当前工程中的体现 |
| --- | --- |
| 内容优先，而非聊天优先 | 剧本、分镜和镜头独立持久化，不依赖对话历史保存业务事实 |
| 模型负责创作，代码负责执行 | Agent 输出经过结构校验，状态迁移、审核和版本一致性由服务端控制 |
| 人工审核是流程的一部分 | 使用 LangGraph `interrupt` 暂停，通过 `Command` 恢复原任务 |
| 数据库记录业务事实 | PostgreSQL 保存运行、内容和审核，Redis 仅承载后台任务队列 |
| 生成能力可以替换 | Provider 适配层与 API、工作流及持久化逻辑分离 |
| 先完成明确链路 | 采用模块化单体 + 独立 Worker，不提前拆分空微服务 |

## 技术架构

```text
React 画布工作台 / OpenAPI
       │
       ▼
    FastAPI ──► PostgreSQL（业务数据 / 内容版本 / 审核 / Outbox）
                       │
                Celery Beat 扫描 Outbox
                       │
                       ▼
                     Redis
                       │
                       ▼
                 Celery Worker
                       │
                       ▼
                   LangGraph ──► Text Provider
                       │
                       ▼
                PostgreSQL Checkpoint
```

API 负责接收请求和查询结果，耗时生成在独立 Worker 中执行。业务表通过 **Alembic** 管理版本；LangGraph checkpoint 内部表通过官方持久化组件单独初始化。

| 层次        | 技术                                                                   |
| --------- | -------------------------------------------------------------------- |
| 前端        | Next.js、React、TypeScript、shadcn/ui（Radix）、Tailwind CSS v4、React Flow |
| 语言与依赖     | Python 3.12、uv                                                       |
| API 与数据校验 | FastAPI、Pydantic v2                                                  |
| Agent 编排  | LangGraph、持久化 checkpoint                                             |
| 业务存储与迁移   | PostgreSQL、SQLAlchemy 2、Alembic                                      |
| 后台任务      | Celery、Redis                                                         |
| 本地运行与检查   | Docker Compose、pytest、Ruff、mypy、GitHub Actions 配置                    |

SQLite 用于单进程开发和测试，不作为生产或并发 Worker 的数据库方案。

当前适合本地演示、架构验证和后续开发，**不应按完整生产系统直接部署到公网**。详细约束见 [架构说明](docs/architecture.md) 与 [开发指南](docs/development.md#当前边界)。

## 快速体验

安装 Docker Compose 后，在仓库根目录执行。若已有 `.env`，请保留现有文件并按示例调整配置。

```powershell
Copy-Item ".env.example" ".env"
docker compose up --build -d
```

- 创作产品：`http://localhost:8080`，首次访问请创建账号。
- Swagger：`http://localhost:8000/docs`
- 默认使用 Mock，无需模型密钥；不会生成真实图片或视频。
- Compose 统一启动内网私有 MinIO、启用版本化的桶初始化、独立文件传输网关及应用服务；MinIO 不发布宿主端口。清理按精确对象版本删除，保留所有文件引用。`/health/ready` 会检查已配置的 S3。MinIO 由固定官方版本源码构建，首次构建较慢；既有本机图片卷继续保留。
- API 调试可使用开发 Service Token：`local-development-token-change-me`，浏览器工作台使用自己的账户会话。
- 首次启动会执行业务表迁移和 checkpoint 初始化，默认凭据仅适用于本机开发。

本地 Python 开发、双审核接口演示、真实模型配置和测试命令见 [开发与运行指南](docs/development.md)。

## 账号模型服务配置

顶栏“模型服务配置”可分别保存文字、图片、视频和语音的地址与模型预设。文字服务默认继承服务器配置，只有用户显式启用自定义文字服务后，新任务才使用该配置。图片、视频、语音当前仅保存预设，不支持生成；真实收费 Provider 联调仍待授权验收。

- 部署新版前按既有流程备份并执行 `alembic upgrade head`（新增迁移 `0003`）；开发代理需保持 `/api/v1` 同源。
- 保存 API Key 前须配置独立 `ARCLIGHT_SERVICE_ENCRYPTION_KEY`：以 `cryptography.fernet.Fernet.generate_key()` 生成，API 与 Worker 使用相同值。密钥不与密文同库存储，不写入 Git，必须安全备份；直接更换会使已保存服务和未结束任务的配置快照无法解密。未配置时仍可保存无密钥预设。
- `ARCLIGHT_MODEL_SERVICE_ALLOWED_HOSTS` 是管理员信任的精确公网 HTTPS 域名 JSON 列表，默认仅 `api.openai.com`。不要加入不受信任或解析到内网的域名；禁止 IP、HTTP、URL 凭证、查询参数、非443端口。HTTP 客户端不跟随重定向；执行任务时再次检查允许列表，管理员撤销域名后，未结束任务可能被阻止。
- 配置按账号隔离、revision 防止陈旧覆盖。读取接口只有 `has_key`，不返回密钥或密文；浏览器不持久化 API Key。工作流启动时捕获加密配置快照，后续修改不会改变等待审核及重试任务；凭证不进入提示词、checkpoint、公开任务详情或审计事件。
- 保存不测试连接、不产生模型费用。启用自定义文字服务后，主动创建的任务将发送故事素材并可能收费，请先确认数据与预算。

## 文件来源与安全回收

项目 Owner 可用 `POST /api/v1/projects/{project_id}/storage-cleanups` 扫描 `TEMPORARY`、`VALIDATED`、`ASSET`、`INTERMEDIATE`、`RENDERED` 或 `SOURCE` 命名空间，每页最多100个对象；`previous_plan_id` 继续下一页。计划只记录候选，观察1小时后，使用 `POST .../storage-cleanups/{plan_id}/items/{item_id}/execute` 逐项执行，24小时后须重新扫描。`GET .../storage-cleanups` 可查看清理结果和失败错误码，失败目标可用同一执行接口重试。

临时上传在签名到期及24小时完成宽限后才可清理；孤立对象保留至少7天，终结任务的中间对象保留至少24小时，活动任务继续保留。每次删除前重新核对所有文件及历史资产版本引用、任务状态和对象身份；登记的候选、旧版本、归档及锁定素材均保留。S3 初始化启用桶版本化，清理计划绑定并删除精确 `VersionId`，最终检查后的外部替换及相同内容的新版本均保留；有引用的 key 保留全部版本。未启用／暂停版本化、旧 null 版本或旧 ETag 计划安全拒绝并返回诊断。本机通过原子移入私有隔离区、复验身份及中断恢复防止删除原路径上的新内容。计划只扫描服务端规范命名空间，按项目写锁串行执行。

`POST /api/v1/projects/{project_id}/files/{file_id}/render-previews` 接受已登记且声明使用权的 PNG／JPEG，创建固定 256×256、24fps、1秒的单图视频预览；`GET /api/v1/projects/{project_id}/render-previews/{run_id}` 返回状态、错误码及成片文件回执。Beat 重投递持久化排队任务，Worker 独立领取，实际 FFmpeg 子进程编码私有中间片段、读回后封装 MP4 并登记不可变文件。失败保留诊断及中间物，可用 `retry_of` 另建重试；任务终态与对象最后写入均满24小时才允许回收中间物，成片与原图继续受引用保护。该入口用于最小真实渲染和存储生命周期，不包含完整时间轴、音频字幕或成片编辑界面。

迁移 `0032` 新增渲染执行历史，有历史时拒绝降级。在线迁移命令由外部事务完整包裹，SQLite 显式开启真实事务；后续历史保护拒绝时，之前的表结构和版本号变更也整体回滚。

项目的 `GET /api/v1/projects/{project_id}/rights` 提供故事、参考图、音频、音乐与字体的来源和使用权声明清单，支持 `category`、`rights_status` 与分页；访问沿用项目成员权限。清单保留精确来源／文件／资产版本、声明人和记录时间，不返回私有对象路径。导入／完成上传须填写来源与授权说明并显式传入 `rights_confirmed: true`；手动任务的未声明来源如实显示 `UNDECLARED`。确认记录表示提交人的使用权声明，系统不自动核验许可证或修改历史声明。

故事原文件使用 `sources/{project_id}/{source_id}` 的服务端对象路径，客户端只接收稳定的来源逻辑引用。`SOURCE` 清理命名空间遵循同一观察期／保留期，所有历史故事来源均为保留根。原字节和解码原文不再作为故事来源表字段保存；正文创作结果和不可变任务输入快照仍属于业务记录。

迁移 `0026` 需要在线运行和已初始化的私有对象存储。升级有故事数据的数据库前，应停止应用写入、备份数据库并确认对象目录／桶配置；迁移逐页复制原文件，核对字节数、SHA-256及解码文本后才移除旧内容列，来源身份、修订记录和任务快照保持。复制失败保留数据库原稿；重试仅复用内容完全一致的对象，冲突对象不会被覆盖。有来源历史时拒绝降级到旧二进制存储结构，离线SQL不能执行本次数据搬迁。仓库测试仅对隔离数据库和测试存储运行此迁移。

## 媒体执行调度

媒体任务由持久化 Outbox、执行租约和心跳驱动；外部提交、查询与取消不持有业务行锁。`ARCLIGHT_MEDIA_EXECUTION_POLICY` 接受 JSON，控制 Provider／项目并发（含 `provider_limits`／`project_limits` 覆盖）、全局／用户每分钟调用数、`paused_providers`、调用超时、总耗时、尝试上限和指数退避。并发／速率／暂停采用当前服务配置，重试和耗时边界随新任务冻结；API 与 Worker 应使用相同配置。

服务明确失败后仅对白名单错误重试；默认自动重试 `PROVIDER_UNAVAILABLE`，`PROVIDER_FAILED` 需显式重试。所有重试均遵守次数、截止时间和退避。超时保留未知结果及并发占用，先按 GEN-04 对账；明确未接收才可受限重试。取消是尽力请求，只有明确终态才能释放并发占用，成功结果可能在取消请求后返回。适配器等待使用有界线程容量，超时不表示外部执行或线程已经停止。

任务的 `schedule`、`calls`、`dead-letter` 和 `replays` 只读子接口沿用项目权限；死信保留安全错误分类和边界。Owner 可对已诊断的明确失败使用 `POST .../generation-jobs/{job_id}/replay`，提交 `expected_revision`、`reason` 和新 `Idempotency-Key`，另建关联原任务／死信的新任务并复验原精确输入和目标 CAS。未知执行不得直接重放。迁移 `0034` 保护调度策略、调用事实、死信及重放关联，有历史时拒绝降级。目前仅有 Mock 媒体 Provider；预算沿用已有项目／剧集／任务／批次限额、不可变预留及结算账本，真实付费服务另行接入。

生成请求可声明 `scheduling_mode: "BATCH"`；缺省为交互任务。服务端将预算批次或多候选请求强制归为批量，显式重试及死信重放继承原分类；客户端不能设置数字优先级。分类与幂等指纹一起冻结，旧请求的指纹仍可重放。默认按交互 3、批量 1 的成功许可份额轮转，同类按项目轮转、项目内按就绪时间 FIFO。`interactive_weight`／`batch_weight` 可调整权重，公平游标持久化；权重不承诺完成时长比例。

Compose 使用独立资源的 `worker-interactive`、`worker-batch`、`worker-scheduler`、`worker-recovery`，分别只消费 `generation.interactive`、`generation.batch`、`scheduler.control`、`generation.recovery`。原 `worker` 只消费 `workflow`。本机启动也必须使用五个独立 Worker 进程，分别传入 `--queues=<队列>` 和唯一 `--hostname=<角色>@%h`；Windows 使用 `--pool=solo`。只启动旧的默认 Worker 无法消费媒体及调度队列。

供应商／项目并发大于 1 时，默认保留 1 个交互槽位，批量不能借用；这会降低纯批量时的利用率。单并发退化为不抢占的加权顺序。全局／用户速率同样在总额度内各保留交互和恢复份额；极小额度不能同时保证各类即时可用。对应配置为 `interactive_concurrency_reserve`、`interactive_rate_reserve`、`recovery_rate_reserve`。尚未消费的有效许可与实际调用共用上述限额，异步／未知调用不会因为 Celery 函数返回而释放。

派发器先在数据库发放短期许可，再发布含 job、事件、许可 ID 和 epoch 的消息。默认许可 30 秒、发布冷却 5 秒、每轮最多 64 条（`permit_seconds`、`publish_cooldown_seconds`、`dispatch_window`）；冷却必须短于许可。Worker 复验许可、权限、精确输入、预算及实时配额，事务内转换为实际调用。Broker 丢消息或发布失败后按同一许可重投；未消费许可过期后递增 epoch，迟到旧消息不能创建 attempt。已消费许可不因到期而释放实际占用或未知费用；恢复队列沿原 attempt 查询。没有许可的旧消息不能直接提交供应商。

项目积压读取为 `GET .../generation-jobs/queue`：按类别区分就绪、退避、待消费许可、执行、未知结果、终态和死信，包含阻塞原因、最老等待及等待分位数、调度心跳。`/{job_id}/queue`、`/{job_id}/permits` 和 `/{job_id}/permits/{permit_id}/events` 提供分类与调度历史，均沿用项目权限与分页。这里的数量是业务任务数；Broker 消息可能重复。运维可用 `docker compose exec redis redis-cli LLEN generation.interactive`（及其他队列名）检查待消费消息，用 `docker compose exec worker-scheduler /app/.venv/bin/celery -A arclight.workers.celery_app:celery_app inspect active_queues` 检查实际 Worker 路由；许可历史可核对过期及重复发布。

升级 `0039` 前必须停止旧 beat／派发器和旧生成消费者，等待或核对在途调用，再迁移并启动新 Worker 组；禁止新旧许可协议混跑。历史输入与 attempt 不改写，来源不明任务保守归批量并保留迁移原因。有分类历史时降级被保护性拒绝；回滚需要恢复协调后的数据库／代码版本，不能直接重启旧消费者。Redis 的 7200 秒 visibility timeout 只处理消息可见性，不代替执行租约或对账。

`GET .../generation-jobs/providers/{provider}/capabilities?model=...` 按项目权限返回已安装 Provider 的版本化能力：参考图数、seed／上限、尺寸／像素／倍数／固定尺寸和画幅、批量上限、查询、取消、幂等及同步／异步方式。创建任务冻结该声明，调用前同时复验冻结声明与当前适配器；旧任务只校验当前能力，不补写历史。`spec.batch_size` 默认1，`spec.require_query`／`spec.require_cancel` 默认false；明确要求不支持能力时拒绝创建。尺寸放在 `output_spec.width`／`height`，参考图只能来自精确输入版本，不能通过参数别名绕过校验。批量成功必须返回对应数量的结果；数量不符按未知／人工处理，不盲目重发。Mock 只模拟规范化结果（最多8项），明确不支持持久查询及取消，不代表真实图片质量或外部服务验收。

## 有限任务上下文

`GET /api/v1/projects/{project_id}/context-policy` 返回任务范围和服务端上限；
`POST /api/v1/projects/{project_id}/contexts/preview` 接收 `task`、`episode_id` 以及合同允许的精确输入，返回只读预览，不创建任务。任务类型包括 `analyze`、`outline`、`script`、`storyboard`、`rewrite`、`art`、`image`、`review`、`producer`。项目成员可读取，跨项目引用拒绝；实际启动仍需 Owner／Editor 权限。

导演／美术任务必须给出 `script_version_id`，改写还需 `rewrite_target`；图片任务需 `shot_id`，审查任务另需 `candidate_version_id` 指定精确待审图片。局部任务仅加载同一精确分镜中的当前／相邻镜头及相关场景，常规参考必须已批准且有效，待审候选可为未批准版本。`asset_version_ids`、`story_entry_ids` 可显式选择相关输入；禁止传入不属于任务合同的范围。

`ARCLIGHT_CONTEXT_LIMITS` 为 JSON：默认 UTF-8 JSON 总量 262144 bytes、64 个资产版本、100 条故事设定、前后各 1 个邻镜、5 条相关历史；硬上限分别为 524288、64、100、2、10。预览请求中的 `limits` 只能调低服务端上限。必需规范、锁定字段及预算完整保留，超限原子拒绝；不截断这些约束。真正调用 Provider 前再次检查上下文与实际任务输入的合计大小。

五个现有文本入口在启动事务中冻结 `context/1` 上下文，复用不可变 DependencyManifest，由 GEN-11 的 VersionBinding 保存逐阶段引用；`GET /api/v1/runs/{run_id}/contexts` 读取这些快照。运行中修改风格、资产、预算或限额不会改写旧输入，重试沿用原清单。编剧→导演串联任务在启动时明确声明本运行后续批准的精确剧本输出，不预造尚不存在的版本。旧运行未保存上下文时返回 `legacy_without_context: true`，不会补读当前事实。专业 Agent 与媒体实际入口由各自任务接入；本功能不代表这些生产器已实现。

启动追溯 `context-trace/1` 另存安全的公开启动输入及摘要、组装版本、故事来源修订、设定修订、视觉规范和精确资产的原始依赖清单摘要。私有对象路径、供应商凭证和图片二进制不会进入这份记录。`GET /api/v1/runs/{run_id}/contexts/{stage}/trace` 返回启动清单、检索轮次和实际消费回执；`through_round=0` 读取启动视图，指定已有轮次可重现该证据前缀。

Owner／Editor 可向 `POST /api/v1/runs/{run_id}/contexts/{stage}/evidence` 提交 `creation_key`（UUID）、`expected_round`（从 0 开始）以及非空的 `asset_version_ids`、`story_entry_ids` 或 `source_ids`。服务端按任务合同鉴权并解析实际内容，顺序追加新清单，关联启动清单和上一轮，不接受客户端自报的证据正文。相同键、相同请求返回原回执（200），新建返回 201；键复用冲突或轮次竞争返回 409。每阶段最多 32 轮，累计独立资产／设定仍受启动时的限额约束，故事来源最多 16 个，累计 JSON 超限拒绝。运行中调高配置不会扩大已有清单的预算。

每个现有文本阶段在首次调用前固定实际消费的证据前缀；图工作流先独立保存不可变消费回执，重试沿用它。单次提炼／大纲在项目锁内将回执与产物一并提交。编剧审核通过后，导演阶段单独选择当时已追加的证据，并将实际批准剧本的精确版本、内容摘要与资产来源记入消费回执，纳入同一累计预算；checkpoint 保存逐阶段引用。后续证据可以继续追加，旧消费回执保持原值。旧版仅有 CTX-01 快照的记录显示 `trace_available: false`，不能补造启动追溯；更早的无上下文记录保持原兼容行为。

图片证据仅保存文件 ID、精确资产版本、checksum、大小和媒体类型。通过 `GET /api/v1/runs/{run_id}/contexts/{stage}/images/{file_id}` 读取实际图片，必须是该阶段清单已包含的图片且当前账号具有项目读取权限；每次校验对象完整性，缺失／损坏拒绝。接口返回 `private, no-store`，不暴露对象存储地址或临时签名。接入实际多图模型协议及专业 Agent 工具循环仍由各自任务负责。
